# Noctalia configuration

Noctalia is the desktop shell on the Niri and labwc machines (miralda, jens,
biene): a native meson/C++ shell with a freeform TOML config and Luau plugins.

## Where the configuration lives

One file, generated by Nix:

```
modules/desktop/noctalia-hm.nix  ->  ~/.config/noctalia/config.toml
```

Colours come from `~/.config/noctalia/palettes/<name>.json`, which the Stylix
target writes; see "STYLIX OWNS SIX OF THESE VALUES" in `noctalia-hm.nix`.

The settings block is deliberately short. Noctalia validates the generated
file at **build time** (`programs.noctalia.checkConfig`, default on, runs
`noctalia config validate`), so the safe shape is to write only what differs
from upstream's defaults and let the validator catch mistakes. To see what you
are overriding:

```bash
noctalia config export full     # the complete default schema, ~750 lines
noctalia config export          # just the active config
```

## Per-user bars

The bar is branched on the username in `noctalia-hm.nix`:

- **lgo** (miralda, jens): the layout captured from jens, with three capsule
  groups and the plugin widgets.
- **sabine** (biene): a minimal, mouse-driven bar — clock and battery centred,
  status on the right, nothing on the left.

Changing either is an edit and a rebuild. A bar rearranged in the settings UI
is written to `~/.local/state/noctalia/settings.toml`, which Noctalia layers
over `config.toml`; for lgo, every switch drops the `bar` and `widget` tables
from that file (`noctaliaBarFromConfig`), so the declared layout always wins.
To keep a UI change, fold it back into `noctalia-hm.nix`.

## Plugins

lgo's are declared in `settings.plugins.enabled` (eleven, from the official and
community catalogues). Noctalia installs them itself: it git-clones its two
default sources into `~/.local/state/noctalia/plugins/sources/` and
materialises the enabled plugins from there.

It attempts that clone **once, at startup**. If the shell starts before the
network is up, the clone fails (`Could not resolve host: github.com` in
`~/.cache/noctalia/noctalia.log`) and every plugin widget is missing until the
next start. The `noctalia-plugin-sources` user unit covers that: at login, if a
clone is missing, it waits for DNS, clones, and tells the running shell to
load the plugins.

To check a machine:

```bash
noctalia msg plugins list | grep -v disabled    # should list all eleven
```

Screenshot and clipboard are built into the shell rather than plugins
(`noctalia msg screenshot-region` / `-fullscreen`,
`noctalia msg panel-toggle clipboard`).

## Keybindings

The compositor bindings call `noctalia msg`, for example:

| Action | Command |
|---|---|
| Launcher | `noctalia msg panel-toggle launcher` |
| Session menu | `noctalia msg panel-toggle session` |
| Volume up | `noctalia msg volume-up` |
| Play / pause | `noctalia msg media toggle` |
| Lock | `noctalia msg session lock` |

`noctalia msg --help` lists the rest. Panel ids are `launcher`, `session`,
`clipboard`, `control-center`, `calendar`, `wallpaper`, `settings`,
`notifications`.
