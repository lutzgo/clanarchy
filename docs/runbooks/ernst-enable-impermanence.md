# ernst — enabling impermanence for real

ernst has been running since 2026-07-23 with **no `@blank` snapshots at all**.
`modules/zfs-impermanence.nix` rolled back to `zroot/root@blank` and
`zroot/home@blank`, both commands ended in `|| true`, and a missing snapshot is
indistinguishable from a successful rollback — so the rollback has been a
silent no-op since install and root has simply accumulated.

The `|| true` is now gone and `clanarchy-impermanence-check.service` fails
visibly while the snapshots are absent. This runbook is the other half: making
the machine actually impermanent.

Read it end to end before starting. Step 4 is a one-way door — after it, every
reboot discards anything on root that is not in `/persist`.

## Why not just `zfs snapshot` and reboot

Because `@blank` is not "empty" — it is *whatever root looked like when you
took it*, restored on every subsequent boot. Snapshot a running, month-old root
and you permanently enshrine that month of accumulation, re-created on every
boot forever. Including things you would rather were gone: ernst's
`/root/.ssh/authorized_keys` currently holds two undeclared `arch-migration`
keys that grant root access and that nothing uses.

So: migrate what must survive, clean what must not, *then* snapshot.

## What was audited

31 MB on `zroot/root`, 107 KB on `zroot/home`. Everything re-derivable except
two directories, which are now persisted by
`machines/ernst/configuration.nix` — container root filesystems (for their
journals) and fwupd's history.

Verified safe to lose:

| Item | Size | Why it's fine |
|---|---|---|
| `/var/cache/fwupd` | 13M | metadata cache, re-downloads |
| `/root/.cache` | 8.4M | nix eval cache |
| `/var/lib/sddm` | 2.6M | regenerated |
| `/var/lib/zerotier-one` | 98K | deliberately not persisted — identity comes from a clan var |
| `/var/lib/AccountsService` | 26K | empty |
| `/home/{admin,go}` | 107K | persisted subdirs are already bind mounts |

Explicitly checked and **not** at risk:

- **SSH host keys** — `sshd_config` points `HostKey` at
  `/run/secrets/vars/openssh/ssh.id_ed25519`, redeployed from a clan var on
  every activation. Nothing in `/etc/ssh` to lose.
- **Root SSH access** — `/etc/ssh/authorized_keys.d/root` is regenerated by
  activation and holds `clanarchy_admin` + `lgo-yubikey`. All recent root
  logins authenticate with the YubiKey key, so access survives. The keys that
  *do* disappear are the two stale `arch-migration` ones, which is a fix.
- `/etc/machine-id`, `/var/log`, `/var/lib/nixos`, `/var/lib/systemd`,
  `/var/lib/sops-nix` — already bind-mounted from `/persist`.

## Procedure

### 1. Deploy the config first

```bash
deploy ernst switch
```

Expect `clanarchy-impermanence-check.service` to **fail**. That is the
tripwire doing its job — it will keep failing until step 4.

### 2. Migrate the newly-persisted directories

The new persist entries bind-mount `/persist/var/lib/...` over the existing
paths. Impermanence does not copy anything, so without this step the existing
contents are simply shadowed by an empty directory.

```bash
systemctl stop container@jellyfin
cp -a /var/lib/nixos-containers /persist/var/lib/
cp -a /var/lib/fwupd            /persist/var/lib/
systemctl start container@jellyfin
```

Verify Jellyfin still serves before continuing.

### 3. Clean the root that is about to become the baseline

```bash
# Undeclared root keys left over from the Arch migration.
# /etc/ssh/authorized_keys.d/root keeps your real access — confirm first:
ssh-keygen -lf /etc/ssh/authorized_keys.d/root
rm -f /root/.ssh/authorized_keys

# Pure caches
rm -rf /root/.cache /var/cache/fwupd

# DynamicUser-era ollama leftover (also handled by its own unit)
rm -rf /var/lib/private/ollama
```

**Do not log out.** Keep this session open until step 5 confirms you can open a
new one.

### 4. Take the baseline — one-way

```bash
zfs snapshot zroot/root@blank
zfs snapshot zroot/home@blank
systemctl restart clanarchy-impermanence-check   # should now succeed
```

### 5. Reboot and verify

```bash
reboot
```

Then, from a *new* connection:

```bash
systemctl status clanarchy-impermanence-check    # active, no failure
ls /root/.ssh/authorized_keys                    # gone, and SSH still worked
systemctl is-active container@jellyfin           # running
journalctl -M jellyfin -n 20                     # journal survived the reboot
```

The last one is the real test of step 2: container journals living through a
reboot is the thing `/var/lib/nixos-containers` was persisted for.

## Rolling back this decision

Destroy the snapshots:

```bash
zfs destroy zroot/root@blank
zfs destroy zroot/home@blank
```

Root stops being reset on the next boot. `clanarchy-impermanence-check` starts
failing again, which is correct — it reports the machine is not impermanent,
which would once again be true.
